# RAG 与数据隔离

故事导入后经人工触发索引：MySQL 保存 KnowledgeDocument/KnowledgeVersion，Qdrant 保存文本分块与向量。每个点含 `workspace_id`、`project_id`、`status`、文档版本、来源 ID、`chunk_kind` 和 `chunk_index`，Scope 与常用过滤字段建立 Payload Index。检索在 Qdrant 查询前加入工作空间、项目和 `ACTIVE` 三重过滤，不通过事后删结果实现隔离。

## 中文切块策略

索引不再按固定字符位置硬切。当前流程先按中文换行、`。！？；` 等自然边界拆成语义单元，再生成两类索引块：

- `semantic`：目标约 680 字符，以完整中文句子/段落为单位，保留相邻语义单元重叠。
- `dialogue`：针对连续对白额外建立约 520 字符的窗口，保留对白前的短叙事、连续发言轮次和中间短动作描写，专门降低“省略主语、代词、上一句是谁说的”这类中文语境丢失。
- 返回文本会在核心块前后补相邻语义单元；向量也基于带邻接上下文的文本生成，因此命中一句对白时不会只把孤立的“我知道”“确定”交给上层模型。
- 同一知识版本重建索引前会删除该版本的旧 Qdrant 点，避免旧固定切块与新切块并存。

## 父子上下文与说话人线索

中文小说的检索块与最终交给 Director 的上下文不再是同一粒度。较小的 `core_text` 负责向量命中；命中后返回约 1150 字符的普通语义父窗口，连续对白则返回约 1650 字符的局部父窗口。这样既避免超大块稀释向量语义，又尽量保留“上一句是谁说的、前面的动作说明了什么、后一句如何承接”。

对白块还保存 `speaker_hints` 与 `speaker_anchors`。它们只来自“顾七问：”“沈青衡道：”等正文中明确出现的说话人线索，不根据单双轮次擅自给无主语对白补 speaker。长对白即使局部窗口没有再次写角色名，也会把最近的明确说话人原句作为锚点交给上层模型；来源仍不足时，Director 必须回答无法确定。

## 检索与重排

检索先走 dense 向量召回，同时使用 Qdrant payload keyword index 对中文 2-gram/3-gram 做独立词法候选召回。两路候选合并后再参考向量相似度、中文 n-gram 重合、明确说话人命中、完整短语以及“说、问、回答、上一句、下一句”等对白意图进行重排。这样即使 embedding 对一个长篇小说里的角色名或短对白区分度不足，角色名、关键物件和原句仍有第二条进入候选集的路径。

最终结果按正文 unit 范围做重叠去重，避免同一段内容同时以 `semantic` 和 `dialogue` 两种块占满 Top-K。Director 最多读取前四条来源，每条保留最多约 1800 字符，并同时收到 `chunk_kind`、`speaker_hints`、`speaker_anchors` 与 `retrieval_mode`，避免最后一公里再次把中文对白上下文截断。

默认 `FakeEmbeddingProvider` 仍只用于确定性测试，但已从“整段连续汉字视为一个 token”改为中文 2-gram/3-gram 特征，使 CI 可以真实暴露角色名、对白短句和省略主语场景的召回回归。设置 `EMBEDDING_MODE=dashscope` 后继续使用 `text-embedding-v4` 的 1024 维真实向量；集合名包含模型与维度摘要，避免不同向量模型混用。

Director 接收检索块时同时获得更完整的邻接文本、分数和块类型。分析提示明确要求：中文连续对白可依据相邻叙事和发言顺序解析省略主语，但来源不足时必须说明无法确定，禁止自行补说话人。检索文本仍作为不可信数据处理，任何写操作最终由 Tool Gateway 权限与人工审批决定。

## 验证

固定测试覆盖：

- Project A 无法召回 Project B 的知识块。
- 中文连续对白被识别成 `dialogue` 块，并保留说话人附近的叙事上下文。
- 查询“某角色为什么继续、对方怎么回答”等包含省略主语的问法时，召回结果必须同时包含角色上下文与关键回答。
- 重新索引同一知识版本不会残留旧切块。

真实模型检索仍应使用项目自己的中文长文本继续做 Recall@K、上下文相关性和最终回答正确率评估；自动化回归解决的是结构与召回退化，不等价于对所有小说文风的语义质量保证。变更向量模型或部署本次切块升级后，应对已有故事重新执行一次索引。
